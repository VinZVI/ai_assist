# Этап 1.1: Упрощенная система согласия и возрастной верификации

## Обзор

Этот документ описывает реализацию упрощенной системы согласия и возрастной верификации для бота Rolet AI. Система обеспечивает юридическое соответствие и защиту от несовершеннолетних пользователей.

## Компоненты системы

### 1. Модель пользователя (User)

Расширена модель пользователя новыми полями для отслеживания состояния верификации:

- `age_verified`: Подтверждение совершеннолетия
- `terms_accepted`: Согласие с условиями использования
- `privacy_policy_accepted`: Согласие с политикой конфиденциальности
- `community_guidelines_accepted`: Согласие с правилами сообщества
- `consent_timestamp`: Время получения согласия
- `consent_ip_address`: IP адрес при получении согласия
- `terms_version`, `privacy_version`, `guidelines_version`: Версии соглашений
- `verification_status`: Статус верификации (pending, verified, rejected, expired)

### 2. Менеджер согласий (ConsentManager)

Управляет процессом получения согласий пользователя:

- `start_onboarding_flow`: Начало процесса регистрации
- `process_consent_response`: Обработка ответа на согласие
- `check_verification_status`: Проверка статуса верификации
- `is_onboarding_required`: Нужно ли пользователю пройти регистрацию
- `complete_verification`: Завершение процесса верификации

### 3. Сервис возрастной верификации (AgeVerificationService)

Обрабатывает проверку возраста пользователя:

- `verify_user_age`: Верификация возраста пользователя
- `is_age_verification_required`: Нужна ли возрастная верификация
- `is_user_verified_adult`: Проверка, подтвержден ли пользователь как взрослый

### 4. Обработчик регистрации (OnboardingHandler)

Управляет процессом регистрации пользователя:

- `handle_start_command`: Обработка команды /start
- `handle_onboarding_callback`: Обработка callback'ов регистрации
- `handle_consent_callback`: Обработка ответа на согласие
- `process_consent_acceptance`: Обработка принятия согласия
- `process_consent_rejection`: Обработка отказа от согласия

### 5. Клавиатуры регистрации (OnboardingKeyboards)

Предоставляет интерактивные клавиатуры для процесса регистрации:

- `welcome_keyboard`: Стартовая клавиатура
- `consent_keyboard`: Клавиатура согласия
- `completion_keyboard`: Клавиатура после успешной регистрации
- `info_keyboard`: Клавиатура для информации о боте

### 6. Middleware верификации (VerificationMiddleware)

Проверяет статус верификации пользователя перед обработкой запросов:

- Блокирует доступ к функциям для неверифицированных пользователей
- Разрешает определенные команды и callback'и без верификации
- Позволяет текстовые сообщения для общения даже без полной верификации

## Процесс регистрации

1. Пользователь отправляет команду `/start`
2. Если регистрация не требуется, показывается сообщение о существующей регистрации
3. Если регистрация требуется, показывается приветственное сообщение
4. Пользователь нажимает "Начать регистрацию"
5. Показывается форма согласия с ссылками на документы
6. Пользователь принимает или отклоняет согласие
7. При принятии согласия обновляются все поля верификации пользователя
8. При отклонении показывается сообщение об отказе

## Безопасность и аудит

- Все действия согласия логируются с IP адресом пользователя
- Версии соглашений отслеживаются для повторной валидации при изменениях
- Middleware обеспечивает защиту от несанкционированного доступа

## Зависимости

- SQLAlchemy для работы с базой данных
- Aiogram для обработки Telegram событий
- Loguru для логирования
- Pydantic для валидации данных

## Конфигурация

Система использует следующие параметры конфигурации:

- `TERMS_VERSION`, `PRIVACY_VERSION`, `GUIDELINES_VERSION`: Версии документов
- `REQUIRE_AGE_VERIFICATION`: Требуется ли возрастная верификация
- `VERIFICATION_TIMEOUT_HOURS`: Таймаут верификации
- `TERMS_URL`, `GUIDELINES_URL`: URL документов
